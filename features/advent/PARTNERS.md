# Партнёрские задания

В оформлении использованы VK, Ozon и Яндекс Музыка. Это выбранные для прототипа бренды, не подтверждённые коммерческие договорённости. Внутри телефона нет служебных пометок.

## Композиция

Сохранены navy, brass, cream и типографические роли Blink. На главной одно дополнительное задание партнёра: логотип32, название, краткое действие и существующая кнопка «число → монета → стрелка». Партнёр меняется по дате: Музыка → Ozon → VK. Остальные задания приложения не помечены чужими логотипами.

Справа сверху два отдельных баланса: билеты ведут в розыгрыш, монеты — в хваталку. Высота касания44, цифры — роль counter, интервалы и радиусы из существующих токенов. В январе билет открывает завершённый розыгрыш, монеты на главной скрыты.

При балансе ниже30 в консоли хваталки вместо платного действия — «задания партнёров». Открывается стандартная шторка со всеми тремя предложениями, без ухода из автомата. Доступны инструкция, выполненное состояние и список с полностью полученными наградами. Закрытие инструкции возвращает список, после начисления кнопка «к хваталке» закрывает оба слоя. Внизу списка — переход к обычным заданиям дня, если партнёрские уже выполнены.

## Выдача

Каждое из трёх заданий даёт30 жетонов один раз за текущий декабрьский день. `S.days[i].partners[id]` хранит отдельное состояние. Главная и шторка используют одни данные. Открытие инструкции и сайта не выдаёт награду.

Событие адаптера приложения:

```js
window.dispatchEvent(new CustomEvent("advent:partner-completed", {
  detail: { id: "music", day: 0 }
}));
```

Допустимые id: `music`, `ozon`, `vk`; day — индекс0–17. Неверные id, другая дата, январь и повторное подтверждение не начисляют награду. После подтверждения обновляются оба баланса, главный список, инструкция и платное действие автомата. Внешний пульт содержит по кнопке подтверждения для каждого партнёра.

В продукте подтверждение поступает от проверяемой серверной интеграции партнёра. В прототипе веб-событие — только контракт для клиента; подключённых партнёрских API и серверной проверки нет. Сайт партнёра открывается отдельно, без передачи персональных данных. Кнопки пульта не входят в продуктовый интерфейс.

## Исходники логотипов

- Яндекс Музыка: [официальные визуальные материалы](https://yandex.ru/support/music/ru/content-requirements/visual), оригинал https://yastatic.net/s3/doc-binary/src/mediaservices/yandex_music_icon_main.png
- Ozon: [Brandlab](https://brandlab.ozon.ru/en/guide/logo_guide), RGB-файл из https://cdn.ozone.ru/s3/ozon-disk-api/Brand_Ozon/Design_Team/Web_Design/Guides_Files/Logo_Ozon_1734337486.zip — белый логотип на синем с исходным охранным полем
- VK: существующий глиф проекта `assets/icons/vk.png`, вырезка экрана настроек через `build_assets.py`

Неизменённые источники — `art/partner-sources/`. Экспорт — `tools/build_assets.py → build_advent_partners()`, также вызывается из `build_advent_journey()`. PNG сжимаются в WebP без изменения цвета/формы; у исходной RGB-доски Ozon меняется только viewBox на готовый синий вариант `(1357.4,286,1080,474.7)`.

## Проверка

Прикидка @2x390×844: оценка8/10 — сохранён вагон и объём автомата, брендинг занимает небольшую часть задания, награда и переход читаются с первого взгляда. Это визуальная оценка, не результат автотестов.

Проверки в `smoke_advent_journey.py`: нулевой и недостаточный баланс, открытие/возврат инструкций, сайт без ложной выдачи, подтверждённая выдача ровно один раз, синхронизация главной и автомата, покупка подарка и новый билет, неверный id/дата, январское закрытие, все выполненные предложения, размеры375/390/430 и ошибки ресурсов. Проверка касаний на физическом устройстве не проводилась.
