# Где учишься?

[Открыть прототип](index.html). Старт — сразу после «возможных друзей». Для проверки выбери любую строку, вступи, нажми «добавить» у знакомого и затем «продолжить». Кнопка «повторить сценарий» на конечном экране относится к стенду. На клиенте в этой точке открывается следующий шаг текущего онбординга.

## Поиск на клиенте

Поле ищет по названию, номеру, городу и типу заведения. Типы «школа», «колледж» и «универ» работают вместе с запросом. Одновременно активен один чип. Повторное нажатие на белый чип снимает фильтр. Крестик в поле очищает только текст. Выдача прокручивается отдельно от поля, фильтров и нижнего действия. Если совпадений нет, показываем звезду и «ничего не найдено».

В строке — герб заведения или синяя иконка с академической шапочкой, название до двух строк и подпись «город · расстояние · друзья». Количество друзей выводим, когда оно известно и больше нуля. Вся строка открывает заведение с соответствующим ID. Исходные состояния поиска находятся в [папке макетов](../../../schools_search).

## Школа в вебвью

Используется `QuestionsApp` из локального репозитория blink-schools, ревизия `e41ae52`. Именно его открывает мобильный маршрут [all/questions](https://herftpok.github.io/blink-schools/#all/questions). При входе виден список людей, рядом находится вкладка «вопросы». В прототип включены карточки вопросов, формы вопроса и ответа из этой вариации.

В исходном экране пользователь уже состоит в заведении. Для входа из онбординга предложены два состояния. Гость видит людей, опубликованные ответы и белую карточку «сообщения из чатика» с фрагментом записи. Карточка открывает чат с этой записью, стрелка возвращает на страницу заведения. Внизу две закреплённые кнопки. Для университета это «вступить в универ» и «я учусь в другом универе», для школы и колледжа подписи меняются по типу заведения. После вступления под списком закреплена тёмная кнопка «продолжить». Когда пользователь отправляет первую заявку в друзья, та же кнопка становится белой. Текст и положение сохраняются при прокрутке. Можно добавить ещё людей и нажать кнопку, когда закончишь. Если отменить все заявки, кнопка снова становится вторичной. Оба состояния ведут к следующему шагу онбординга. Заявка, отправленная до вступления в открытой школе, тоже учитывается.

| Действие | До вступления | После подтверждённого вступления |
|---|---|---|
| «Пропустить» на поиске | Следующий шаг онбординга, учебное заведение не выбрано | — |
| Стрелка или системный жест назад внутри школы | Из чата — на предыдущий экран. На корневой странице — обратно к поиску | Во вложенном экране — на уровень назад, в открытой шторке — закрыть шторку. На корневой странице — следующий шаг онбординга |
| Крестик вебвью | Закрыть школу и восстановить поиск | Закрыть школу из любого раздела и перейти к следующему шагу онбординга |
| «Я учусь в другой школе» и аналоги | Вернуться к сохранённой выдаче для выбора другого заведения | — |
| «Продолжить» | — | Закрыть вебвью и завершить шаг выбора |

Стрелка и крестик постоянно находятся в верхней панели контейнера. Они доступны, пока загружается веб-страница, при прокрутке, во вложенных экранах и при ошибке загрузки. После выхода гостя восстанавливаются текст, чип, прокрутка и фокус на выбранной строке. Клавиатура сама не открывается.

## Передача результата клиенту

1. При открытии сохранить запрос, выбранный тип и позицию строки. Передать в вебвью ID заведения и источник входа `onboarding`. Открытие карточки само по себе не меняет членство.
2. В продукте школа отправляет запрос на вступление. Пока он выполняется, блокировать повторное нажатие. При ошибке оставить пользователя гостем и предложить повторить. После успеха передать клиенту ID и подтверждённый статус членства.
3. Клиент принимает результат только от открытой страницы для текущего ID, сохраняет его и подтверждает получение. Повторный успех для того же заведения безопасен. Вебвью может показать «продолжить» после подтверждения. Если страница перезагрузилась, клиент повторно передаёт сохранённое состояние.
4. Крестик обрабатывает контейнер. Стрелка сначала предлагает вебвью вернуться на предыдущий внутренний экран. На корне оба выхода выбирают назначение по сохранённому статусу. Если человек закрыл страницу во время запроса или ответ потерялся, клиент сверяет членство с сервером до выбора назначения. Успешное вступление завершает шаг ровно один раз. При отсутствии членства клиент восстанавливает поиск.
5. При пропуске клиент сохраняет `skipped` и продолжает онбординг. При вступлении сохраняет `joined` и ID. Новый вход в приложение продолжает с сохранённого шага.

На стенде границу клиента и вебвью воспроизводят основная страница и локальный iframe. Обмен идёт через события `ready`, `state`, `joined`, `requestChanged`, `back`, `close` и `continue`. Вступление подтверждается локально. Каталог, расстояния и люди демонстрационные. Колледж добавлен для проверки одноимённого чипа. Производственные запросы и сохранение в профиле предстоит подключить на клиентах.

## Запуск и проверка

Из корня Blink DS запустить `python3 prototype/tools/serve.py`, затем открыть [экран поиска](http://localhost:8765/features/onboarding-school/). Готовая сборка школы лежит рядом с экраном и работает без GitHub Pages. Проверка сценариев — `python3 prototype/tools/smoke.py onboarding-school`.

Для обновления школьных компонентов запустить `python3 prototype/features/onboarding-school/source/build.py ~/Downloads/schools`. Сборка использует установленные зависимости школы и применяет адаптацию к временной копии исходников. Папка `~/Downloads/schools` остаётся источником. Веб-копии графики экрана поиска собирает `build_onboarding_school()` из `prototype/tools/build_assets.py`.
